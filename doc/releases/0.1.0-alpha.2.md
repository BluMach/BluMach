# BluMach 0.1.0-alpha.2 — classic Windows preview

Second experimental preview of the classic Qt 6 product, dated
2026-10-12. Downloads are listed on the
[GitHub release page](https://github.com/BluMach/BluMach/releases/tag/v0.1.0-alpha.2).
CoreMach is a separate project: this
preview uses the classic emulator, not the portable engine.

## Changes since alpha.1

- Experimental catalogue creation and configuration selection for Olivetti
  M15 and M15 Plus, Toshiba T3200, T5100 and T5200. These are separate machine
  models, not interchangeable memory/storage presets.
- M15 and M15 Plus sit directly in the Olivetti M range; format and period
  remain filters rather than artificial model-number subfamilies.
- Expanded Olivetti M and Toshiba T histories with chronological reference
  tables, sources and explicit catalogue availability in English, Spanish,
  French, Italian and Portuguese. An additional historical row does not
  enable emulation or certify that model's hardware.
- Documented creation profiles and firmware requirements for the new models;
  pending or unsupported options remain identified rather than approximated
  silently as another commercial configuration.
- M15 LCD presentation revised toward a reflective green panel with dark
  blue-green characters, rather than a black screen with green phosphor text.
- Device-declared screen controls under View → Screen, with model-specific
  limits described in the sheets. Software presentation adjustments are not
  a claim of physically accurate analogue LCD/plasma behaviour.
- Catalogue and machine-sheet text refinements across the five languages.
- M15 Plus HDU: expose DMA-ready status before completion, preventing the
  BIOS from exhausting its wait on each FDISK sector write. Reset also cancels
  pending controller work before the BIOS probes the HDU again.

Olivetti PCS 86, PCS 286 and PCS 386SX remain offered. Inherited emulator
machines remain selectable independently of the curated collection. Deferred
BluMach models remain filtered out of new configuration choices. A previously
loaded VM retains its machine identity without unlocking it as a new choice.

## Setup and firmware

The [alpha.1 setup guide](0.1.0-alpha.1.md) still describes ZIP extraction,
the independent BluMach VM library, configuration filenames and root ROM
folder selection. It also records the original PCS firmware layouts.

The new machine sheets identify required firmware and creation choices.
Place entitled local firmware under the root ROM folder selected in
Preferences; do not pass its parent as the ROM root. The configuration combo
requires both release eligibility and locally available machine firmware.
The catalogue can still be browsed without firmware.

For M15 Plus BIOS 1.10, the required relative filename is
`machines/olivetti_m15plus/Olivetti-M15-Plus-BIOS-1.10.bin` beneath the ROM root.
The image is 32,768 bytes; SHA-256:
`B70E9FE50022025F0652B4E7ACE52D73390733456A7585A26749BBA925AC4636`.
On Windows the default shared local location is `%LOCALAPPDATA%/BluMach/roms`.
When a ROM root is selected explicitly, use that folder instead. Moving the
application does not copy a separately configured firmware library.

T5100 currently uses compatibility video firmware because its original AGS
ROM remains absent. Do not describe that configuration as fully faithful.
Other firmware, peripheral and commercial-variant limits remain in the
individual sheets. A generated blank HDD needs guest partitioning/formatting
and an operating system; no DOS or machine software is supplied.

ROMs, BIOS, operating systems, applications and private preservation inputs
must not be included in source or binary release assets. Test storage using
private writable copies, not archival originals. Reusing configuration text
does not itself copy the disks referenced by its paths.

## Validation and follow-up

Automated catalogue, version, configuration and screen-control tests are
regression checks, not proof of complete hardware fidelity. The machines
remain experimental; no exhaustive firmware, software or expansion matrix
is claimed. Previous quick audio evidence does not validate audio expansions
for these portables; M15/M15 Plus do not offer ISA sound-card upgrades.

The M15 Plus owner repeated MS-DOS 3.20 FDISK after the HDU correction on
2026-10-12 and confirmed that answering «S» now continues. A firmware-free
contract exercises the real HDU state machine, first-cylinder DMA writes,
partition-sector readback, DRQ/IRQ status, reset cancellation/recovery and
PCS 86 isolation. Passing that test does not certify FORMAT, every DOS
version, the physical SCSI bridge or every warm-reset scenario.

Further acceptance work remains:

1. Smoke-test fresh profiles of the five added models with entitled local
   firmware: POST/boot, keyboard, supported storage, screen controls,
   pause/resume, reset, close/reopen and configuration persistence. Record
   exact BIOS, RAM, media and any failures, without treating one successful
   combination as validation of all variants.
2. Check the original three PCS models for regressions. Preserve known
   approximations and untested cases in the published notes.
3. Extend destructive HDU testing using disposable copies: FORMAT, operating
   system installation, cold boot and repeated warm resets. Keep the original
   floppy and hard-disk preservation inputs unchanged.

The Windows ZIP is accompanied by SHA-256 and a build manifest tied to its
source commit. Catalogue, identity/version checks, Python tests, CTest and
startup with the development toolchain removed from PATH are release checks.
The package contains no firmware or guest media.

Linux/macOS packaging metadata shares this version, but that alone does not
certify a distributed build on those systems. Report bugs with version,
host, model, BIOS selection, RAM, storage geometry and reproduction steps.
Enable a startup log with `--logfile path` (`-L path`) when useful.
